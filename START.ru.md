# Как установить и запустить Codex Analytics

## Для обычного использования

1. Откройте [страницу релизов](https://github.com/Noki1945/Codex-Analytics/releases) и скачайте файл `codex-analytics-1.0.0.vsix` из раздела **Assets**.
2. Запустите Visual Studio Code.
3. Откройте **Расширения** сочетанием **Ctrl+Shift+X**. Нажмите **…** вверху панели и выберите **Установить из VSIX… / Install from VSIX…**.
4. Выберите скачанный файл. Если VS Code предложит перезапустить расширения, нажмите соответствующую кнопку.
5. Нажмите **Ctrl+Shift+P**, введите **Codex Analytics: Open Dashboard** и нажмите **Enter**.

Также можно нажать значок диаграммы **Codex Analytics** в левой панели VS Code. Команда Open Dashboard удобнее для большого окна аналитики.

**Node.js, npm и API-ключ для готового VSIX не нужны.** Для получения лимитов нужен установленный Codex с вашей обычной действующей авторизацией.

## Первое открытие

История загружается автоматически из каталога `~/.codex/sessions` или `CODEX_HOME/sessions`, если задан CODEX_HOME. Нажмите **Обновить**, чтобы перечитать новые события. Импорт не запускает задачи Codex и не изменяет исходные журналы.

В бете 0.2 стандартный импорт также включает `archived_sessions`. Чтобы добавить другой каталог, нажмите **Импорт папки** и выберите папку с журналами Codex. Существующие задачи сохраняются, дубликаты распознаются по идентификаторам. Фильтры «Операция» и «Качество 5ч» уточняют выборку; кнопки CSV/JSON экспортируют только выбранные задачи. Расчёт прогноза использует эту же отфильтрованную историю.

- **Dashboard** — сводка, активность и полнота данных.
- **History** — задачи, поиск, фильтры и страницы истории.
- **Operations / Models / Projects** — сравнение наблюдений.
- **Limits** — нажмите **Получить из Codex App Server**, чтобы запросить актуальные проценты и время сброса.
- **Forecast** — выберите модель, операцию, единицу и объём, затем нажмите **Рассчитать**. Нужны минимум пять подходящих наблюдений для каждого показателя. Сначала обновите Limits, если нужна оценка попадания в оставшийся лимит.
- **Finance** — введите собственные цены и условия. Пустые цены не заменяются вымышленными.
- **JSON / CSV** — экспорт агрегированной истории в выбранный файл.

## Если история или лимиты не появились

Откройте настройки **Ctrl+,** и найдите `codexAnalytics`.

- `sessionsPath` — укажите каталог с журналами `.jsonl`, если он отличается от стандартного. Пример для Windows: `C:\Users\ИМЯ\.codex\sessions`.
- `codexPath` — при ошибке «Codex не найден» укажите полный путь к `codex.exe`. Расширение также пытается найти его внутри установленного официального расширения Codex.
- `autoImport` — автоматическое обновление истории. При отключении уже сохранённая история остаётся доступной.
- `includeArchived` — включать архивные сессии при стандартном пути журналов.
- `pollSeconds` — интервал автоматического обновления, минимум 15 секунд.

Подробные ошибки находятся в **Вид → Вывод / View → Output**, канал **Codex Analytics**. Если база занята другим окном, дождитесь завершения импорта в нём и нажмите «Обновить».

«Недостаточно данных» — нормальный результат при короткой истории. Прогноз не придумывает отсутствующие измерения. Все проценты расхода показываются в процентных пунктах; они не являются точным счётом за конкретную операцию.

## Обновление

Установите новый VSIX тем же способом и перезапустите расширения по предложению VS Code. Перед переходом со старого формата базы версия 0.1.2 сохраняет локальную резервную копию `analytics.sqlite.v1.bak`. Исходные журналы не удаляются.

## Запуск разработчиком

Для сборки из исходников нужен Node.js 22 LTS:

```sh
npm ci
npm test
npm run package
```

В каталоге проекта появится устанавливаемый VSIX. Для отладки откройте проект в VS Code, нажмите **F5**, затем выполните **Codex Analytics: Open Dashboard** в окне Extension Development Host.
